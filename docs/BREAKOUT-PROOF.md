# The Breakout proof (a bigger scene)

2026-09-30. Pong was 6 nodes: no physics, no textures, no resources. To raise confidence, a Breakout level was built
the same way (TypeScript definition -> registry types -> shared type -> validator -> emitter) and checked three ways.
The scene definition is `scene-defs/breakout.def.ts` in the game repo; its scripts are TypeScript compiled by tstogd.

## What the scene has that Pong did not

| | Breakout |
| --- | --- |
| Nodes | **142** (Pong: 6) |
| Generated by loops | 40 bricks (5 rows x 8), each a `StaticBody2D` with a sprite and a collision shape |
| Resources | **46** shape resources (`RectangleShape2D`, `CircleShape2D`) and **7** external resources (4 scripts, 3 textures) |
| Shared texture | one brick texture used by 40 sprites (one resource id) |
| Node types | physics bodies, `Area2D`, `Camera2D`, `CanvasLayer`, `Label`, `Timer`, `Sprite2D`, plain nodes |
| Property kinds | numbers, booleans, strings with quotes and non-ASCII characters, colours and vectors (raw), resources, script variables |
| Size | 102 lines of TypeScript -> 708 lines of `.tscn` (the loops are where TypeScript pays off; Pong was not shorter) |

## Check 1: does Godot load exactly what the tree says?

`npm run verify:breakout`. The tree is exported to JSON (`scene-defs/verify/export-expected.ts`). Godot loads the emitted
scene and `verify-scene.gd` compares every node's class, script and every property with the JSON, including the
fields inside shape resources, and flags nodes that are present but not in the tree. Result: **142 nodes, 706 checks, 0 problems.**

This check only counts if it can fail, so seven corruptions were made to copies of the scene. **All seven were caught**, each with a precise message:
a brick moved by 1 pixel, a `script` line removed, a texture path swapped, a shape size changed by 1, a script variable
written before its script line (the Pong bug), an extra node added, and a label string edited. The same verifier also passes on the Pong scene (41 checks).

## Check 2: does it play?

`npm run sim:breakout`. The real physics, headless, at 60 frames per second, two scenarios:

| Scenario | Result |
| --- | --- |
| Perfect paddle (follows the ball) | All **40 bricks cleared in 85.7 s**. Ball stayed within x 8..1144 and y 8..584: exactly the inner edges of the walls, no tunnelling. Score label "Score 400". Never lost. |
| No paddle | One brick hit, then the ball reached the death zone at 1.9 s. The `body_entered` signal (connected in code) set the lost flag. Label "Score 10". |

This exercises what the tree comparison cannot: that shape sizes and positions really collide, that the walls hold, and that typed `get_node`
paths (including `Hud/ScoreLabel`, through a `CanvasLayer`) work in the scripts generated by tstogd from the emitted scene.

## Check 3: do the tools catch mistakes in a scene this size?

Six deliberately broken variants of the definition:

| Mistake | TypeScript (editor) | Validator |
| --- | --- | --- |
| A brick loses its collision shape | nothing | warning naming the brick |
| Loop bug: brick names repeat | nothing | error: sibling names must be unique |
| Texture path typo | error, "not assignable to `TexturePath`" | **ok: no issues** |
| Script path typo | error, with "Did you mean ...?" | **ok: no issues** |
| Class typo (`StaticBody2Dd`) | error, "Did you mean `StaticBody2D`?" | error, same hint |
| A Resource used as a node (`CircleShape2D`) | error | error: "is a Resource, not a Node" |

Structure is the validator's job; typos are the compiler's. Path typos are caught **only** by the typed registry vocabulary.

## Findings

1. **Registry keys get renamed.** Adding `breakout/main.gd` and `breakout/paddle.gd` made the registry rename Pong's
   `Scripts.main` and `Scripts.paddle` to `scriptsPongMain` and `scriptsPongPaddle`. Pong's definition stopped compiling (loudly, which is the
   good part) and had to be edited. The docs had warned about this; this is the real cost. Open question: always include the folder in keys?
2. **The emitter cannot share a resource between nodes.** The 40 identical brick shapes became 40 separate shape resources. Godot
   loads them fine; it is bloat, and editing one brick's shape in the editor would not change the others. Sharing one is a missing feature.
3. **The validator does not check file paths.** A wrong script or texture path passes it. The compiler catches it, but only if the
   tree uses the registry's types. An untyped tree is unchecked. (An existence check was built earlier on the shelved
   `layer2-validation` branch, then reverted.)
4. **What the scene could not say.** Groups (bricks would normally be in a "bricks" group), signal connections (`[connection]` lines) and
   instanced scenes cannot be written by the emitter. Breakout worked around them in code (`connect(...)` in `_ready`, counting the `Bricks` children).
5. **The typed pipeline worked end to end.** Emitted scene -> tstogd typings -> typed `get_node`: no errors on the second `convert` pass (the
   first pass reports errors because the typings do not exist yet; that is the known ordering).

## Not tested

Groups, connections, instanced scenes, animation, audio, tile maps, UI themes; the scene opened in the Godot editor (it was
loaded through Godot's loader); Windows; other Godot versions; the editor plugin on a scene this size with the new shared type.

## Tools worth keeping

`verify-scene.gd` and `export-expected.ts` are generic: any definition can be checked against what Godot loads. They live in the game repo for now; they are
candidates for the engine. The physics simulation is specific to Breakout.
